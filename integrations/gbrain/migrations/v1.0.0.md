# Migration: Pre-v1.0.0 → v1.0.0

**Affected:** Users of early CertainLogic GBrain integration (before skill standardization)

## What Changed

| Component | Before | After |
|---|---|---|
| Skill file | `certainlogic-verify.md` (no frontmatter) | `skills/CYL-verify.md` (full GBrain frontmatter) |
| Skill ID | none | `certainlogic-cyl-verify` |
| Version | not tracked | `1.0.0` (semver) |
| Category | not specified | `brain` |
| Triggers | implied by agent | explicit list in frontmatter |
| Health checks | none | `env_exists` + HTTP probe |
| Audit logging | SQLite schema only | Full audit protocol with SHA-256 hashes |
| Cross-modal | manual configuration | Standard `review_pairs` in `cross-modal.yaml` |

## Rewrite Steps

### Step 1: Backup current state

```bash
cp -r /path/to/gbrain/skills/certainlogic-verify* /backup/gbrain-skills-$(date +%Y%m%d)/
cp /path/to/gbrain/skills/conventions/cross-modal.yaml /backup/
```

### Step 2: Remove old skill

```bash
rm /path/to/gbrain/skills/certainlogic-verify.md  # or whatever it was called
# Remove any old conventions entries that reference the old skill
```

### Step 3: Install new skill

```bash
cp integrations/gbrain/skills/CYL-verify.md /path/to/gbrain/skills/
```

### Step 4: Update cross-modal review configuration

Edit `/path/to/gbrain/skills/conventions/cross-modal.yaml`:

```yaml
# REMOVE old entries referencing "certainlogic-verify" or similar

# ADD new review_pairs
cross_modal_review:
  enabled: true
  review_pairs:
    - trigger_skill: enrich
      review_skill: certainlogic-cyl-verify
      when: "Tier 1 enrichment or any company/person data"
    - trigger_skill: idea-ingest
      review_skill: certainlogic-cyl-verify
      when: "page contains >3 numerical claims or >2 quotes"
    - trigger_skill: media-ingest
      review_skill: certainlogic-cyl-verify
      when: "enrichment updates >5 entities"
```

### Step 5: Verify environment

```bash
export BRAIN_API_KEY="your_key_here"
# If unset, skill will degrade gracefully but skip validation
curl -s http://127.0.0.1:8000/health | grep ok || echo "⚠️  Brain API not running"
```

### Step 6: Validate installation

```bash
cd /path/to/gbrain
gbrain doctor
gbrain skillpack-check
# Expected: certainlogic-cyl-verify: ✅ installed, health checks passing
```

### Step 7: Test with a sample enrichment

```bash
# In your gbrain instance, trigger an enrich on a company with known data
# Verify that compiled truth contains [Source: CertainLogic validated, ...]
# Verify that audit log has entries
```

## Breaking Changes

1. **Old skill file name no longer recognized.** If your agent prompts or conventions reference the old filename, update them.
2. **Frontmatter now required.** Any custom modifications to the old skill body need to be re-applied to the new SKILL.md format.
3. **Audit log schema changed.** Old audit entries remain readable but new entries use the v1.0.0 format with SHA-256 hashes.

## Rollback

If something breaks:

```bash
rm /path/to/gbrain/skills/CYL-verify.md
cp /backup/gbrain-skills-*/certainlogic-verify.md /path/to/gbrain/skills/
# Restore old cross-modal.yaml from backup
```

Then file an issue: https://github.com/CertainLogicAI/hallucination-guard/issues

## After Migration

You should see:
- `gbrain skills` lists `certainlogic-cyl-verify` with version `1.0.0`
- Health checks pass for both `env_exists` and HTTP probe
- First enrich shows `[Source: CertainLogic validated, ...]` in compiled truth
- Audit log at `~/.certainlogic/audit.jsonl` (or your configured path) has entries
