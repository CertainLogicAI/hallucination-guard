# A/B Testing Framework for Cold Outreach

## What to Test (in priority order)

### 1. Subject Lines (highest impact)
Test one variable at a time:

| Variable | Version A | Version B |
|----------|-----------|-----------|
| **Personalization** | "Quick question" | "Quick question about [Company]" |
| **Length** | "Growth idea" | "3 ways [Company] could double demos this quarter" |
| **Curiosity** | "[Company] + [solution]" | "Noticed something about [Company]" |
| **Numbers** | "Improve your pipeline" | "47% more replies in 30 days" |
| **Question vs Statement** | "Struggling with [pain]?" | "[Pain] is costing you [X]" |

**Winner criteria:** 100+ sends per variant, measure open rate. Run for 5-7 days.

### 2. Opening Lines (second highest)
| Variable | Version A | Version B |
|----------|-----------|-----------|
| **Observation** | "Saw [Company] just raised..." | "Noticed your team is hiring for..." |
| **Compliment** | "Love what you're doing with..." | Skip compliment, straight to value |
| **Question** | "Are you still handling [X] manually?" | "Most [role]s I talk to waste 5hrs/week on [X]" |
| **Social proof** | Lead with reference client | Lead with their pain |

**Winner criteria:** Same volume, measure reply rate.

### 3. CTA (third)
| Variable | Version A | Version B |
|----------|-----------|-----------|
| **Specificity** | "Worth a chat?" | "Free Tuesday at 2pm?" |
| **Commitment** | "15 min call?" | "Can I send a 2-min video?" |
| **Permission** | "Mind if I send more detail?" | "Here's the case study: [link]" |
| **Binary** | "Yes or no — is this relevant?" | "Want me to run the numbers?" |

## Testing Rules

1. **One variable per test** — subject, opening, or CTA. Never all three.
2. **Minimum 100 sends per variant** — under 100 is noise, not signal.
3. **Same list quality** — randomly split your list, don't cherry-pick.
4. **Same send time** — send both variants simultaneously or alternate evenly.
5. **Wait 5-7 days** — late replies skew results if you call it too early.
6. **Track the right metric:**
   - Subject line test → open rate
   - Body/opening test → reply rate
   - CTA test → meeting booked rate

## Common Pitfalls
- **Calling it too early** — 30 sends proves nothing
- **Testing too many things** — you won't know what worked
- **Ignoring reply quality** — high reply rate with "unsubscribe" responses isn't winning
- **Never iterating** — test → learn → test again. Winners become the new control.
- **Testing irrelevant variables** — if open rate is 60%, stop testing subjects. Fix the body.
