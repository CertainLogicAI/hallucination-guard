# Brain Capture Policy — Mandatory Data Retention

**Effective:** 2026-05-06 immediately  
**Enforced by:** Alex (automatic) + Anton (manual review)  
**Status:** Hard rule — no exceptions

---

## Core Rule

> **ALL data, decisions, analysis, and claims generated by CertainLogic MUST be captured in the Company Brain (GBrain) before being acted upon externally.**

**Why:** Documentation of claims is our primary differentiator. Verifiable > viral.

---

## What "All Data" Means

| Data Type | Where It Goes | When | Owner |
|-----------|--------------|------|-------|
| **Code changes** | Git repo (already captured) | On commit | Alex (auto) |
| **Decisions** | `family/work/decisions/{topic}` | At decision time | Anton |
| **Market research** | `family/market/{topic}` | On discovery | Alex |
| **Competitor intel** | `family/market/competitors/{name}` | On receipt | Alex |
| **External feedback** | `family/comms/feedback/{date_source}` | Within 1 hour | Alex |
| **Public claims** | `family/comms/claims/{claim_id}` | BEFORE posting | Alex (gate) |
| **Product features** | `family/work/features/{feature}` | At spec time | Anton + Alex |
| **Metrics/traction** | `family/work/metrics/{date}` | Daily | Alex (auto via cron) |
| **Ethos updates** | `family/who/anton/ethos_updates` | On change | Anton |
| **Errors/incidents** | `family/work/incidents/{date}` | Within 30 min | Alex |

---

## Public Claims Gate

**HARD RULE:** No public claim (X post, investor pitch, marketing copy) without supporting documentation in GBrain.

**Workflow:**
1. Anton drafts claim
2. Alex stores in `family/comms/claims/pending/{claim_id}`
3. Alex verifies evidence exists in brain or filesystem
4. If verified → Anton approves → post
5. If unverified → flag for Anton → DO NOT POST

**Example:**
- Claim: "Our system reduces token costs by 60%"
- Required in brain BEFORE posting:
  - `family/work/metrics/2026-05-06` showing actual cost data
  - `family/work/features/token_reduction_engine` describing how it works
  - `family/comms/claims/pending/token-cost-60pct` with evidence links

---

## Enforcement

### Automatic (Alex)
- Every git commit → logged in brain under `family/work/commits/{date}`
- Every model call → logged in brain under `family/work/llm_usage/{date}`
- Every external API call → logged with source attribution
- Every cron run → logged in brain under `family/work/cron_runs/{date}`

### Manual (Anton)
- Significant decisions → Anton writes summary, Alex stores
- External meetings → Anton provides notes, Alex stores
- Customer conversations → Anton summarizes, Alex stores

### GateKeeper (Alex)
- Before ANY X post → Alex checks `family/comms/claims/pending/`
- Before ANY investor update → Alex verifies metrics in brain
- Before ANY external communication → Alex logs in `family/comms/external/`

---

## Storage Format

**Every brain page MUST include:**
```yaml
---
type: [fact | decision | claim | feedback | metric | incident | market_intel]
author: [anton | alex | system]
created: YYYY-MM-DD HH:MM
source: [where this came from]
reliability: [1-10, required for external feedback only]
verified: [yes | no | pending]
---
```

**Content rules:**
- No placeholders. Real data or flag as draft.
- Link to supporting evidence (git commit, file path, screenshot)
- If claim, include "what would disprove this" for falsifiability

---

## What Happens If We Skip This

| Violation | Consequence |
|-----------|-------------|
| Public claim without brain doc | Post blocked by Alex (hard rule) |
| Decision not logged | Flagged in next daily review |
| Competitor intel not stored | Lost to memory reset |
| Feedback without reliability score | Alex adds as "unverified external" |

---

## Verification

**Weekly audit (Alex):**
- Scan `family/comms/claims/pending/` — all should be resolved (posted or rejected)
- Check `family/work/decisions/` matches Anton's verbal decisions
- Verify no unverified claims exist in public channels

**Monthly audit (Anton + Alex):**
- Review completeness: did we store everything?
- Review quality: is the documentation useful?
- Fix gaps, update templates

---

## Anti-Patterns (What NOT To Do)

- ❌ Post on X first, document later → VIOLATION
- ❌ Make a claim in a meeting, never write it down → VIOLATION
- ❌ Store a claim without evidence → VIOLATION (flag as unverified)
- ❌ Delete or edit brain docs without audit trail → CRITICAL VIOLATION
- ✅ Store first, verify, then post
- ✅ Document assumptions and caveats explicitly
- ✅ Log what would disprove your claim

---

## Rationale

This isn't bureaucracy. It's our competitive advantage:

1. **Investors trust us** because we can point to specific data backing every claim
2. **Customers trust us** because our audit trail is real, not aspirational
3. **We trust ourselves** because our decisions are documented and reviewable
4. **We ship faster** because we don't waste energy remembering what we decided

The Company Brain is useless if it's empty. This policy ensures it's always populated.
