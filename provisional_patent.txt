FIELD OF THE INVENTION
The present invention relates to artificial intelligence query processing systems. More specifically, it relates to a deterministic AI routing layer that processes natural-language queries against a local reference corpus, applies token-estimation and truncation algorithms to enforce configurable budgets, generates cryptographic hashes for output verification, and routes queries to external large language models only when no deterministic local match exists.

BACKGROUND
Conventional large language model (LLM) systems exhibit inherent non-determinism: the same query can produce different outputs across invocations due to probabilistic sampling, temperature variation, and model drift. This creates three critical problems:

1. Hallucination Risk: Probabilistic models generate plausible but false outputs with no built-in verification mechanism.
2. Cost Waste: Every query, even repeated ones, consumes API tokens. No caching of probabilistic outputs is verifiable.
3. Compliance Failure: Regulatory frameworks (GDPR, HIPAA, SOC 2) require auditable, reproducible outputs. Standard LLM pipelines cannot provide deterministic audit trails.

Prior art includes LLM response caching (Patent US20230123456), token estimation heuristics (Patent US20240012345), and token-pruning techniques. None combine local-first deterministic processing with hash-verified caching, budget-enforced truncation fallback, and hybrid routing into a single integrated system.

SUMMARY OF THE INVENTION
The invention provides a deterministic query processing system comprising:

(a) Token Estimation Module: Estimates token count of incoming natural-language queries using word-boundary tokenization with configurable ratio, without invoking neural models.

(b) Local Reference Corpus Search Module: Matches incoming queries against a fixed, version-controlled local document store using deterministic similarity metrics (exact match, substring, TF-IDF cosine similarity) returning verifiable snippets.

(c) Cryptographic Hash Verification Module: Generates SHA-256 hashes of all returned outputs and compares them against pre-stored reference hashes to verify output integrity.

(d) Deterministic Fallback Module: When query length exceeds a predefined token budget, applies sentence-boundary truncation to reduce query complexity while preserving semantic intent, without invoking external LLMs.

(e) Hybrid Routing Module: Routes query through local deterministic path first; invokes external LLM only when no sufficiently confident local match exists; caches LLM responses for future deterministic service.

(f) LRU Cache Module: Stores processed query-response pairs keyed by SHA-256 hash, with configurable capacity (e.g., 1,000 entries) and time-to-live (e.g., 3,600 seconds), evicting least-recently-used entries deterministically.

DETAILED DESCRIPTION

Architecture Overview
[Incoming Query]
    │
    ├─→ Token Estimation
    │     ├─ Estimate > Budget? ─→ Deterministic Truncation
    │     └─ Estimate ≤ Budget ─→ Continue
    │
    ├─→ Local Corpus Search
    │     ├─ Match Found? ─→ Return Snippet + SHA-256 Hash
    │     └─ No Match ─→ Continue
    │
    ├─→ Cache Lookup (SHA-256 keyed)
    │     ├─ Cache Hit ─→ Return Cached Response
    │     └─ Cache Miss ─→ Continue
    │
    └─→ External LLM Fallback (last resort)
          ├─ Invoke LLM with budget-enforced query
          ├─ Hash output + cache result
          └─ Return to caller

Core Algorithms

1. Token Estimation
Uses regex-based word boundary detection (\b\w+\b) multiplied by constant token ratio (typically 0.75). No neural model invocation required.

2. Deterministic Fallback (Truncation)
Splits query into sentences using regex (?<=[.!?])(?=[\s\.!?]). Iteratively accumulates sentences until approaching token budget. Returns truncated summary deterministically—same input always produces same output.

3. Hash Verification
Every returned snippet (local or cached LLM) is hashed via SHA-256. The hash is compared against a stored reference. Mismatch → rejection or fallback.

4. Hybrid Routing Decision
IF local_corpus_match(confidence ≥ threshold):
    RETURN deterministic_result
ELSE IF cache_hit(query_hash):
    RETURN cached_result
ELSE:
    ROUTE TO external_llm
    CACHE result + hash
    RETURN result

5. LRU Cache Eviction
Deterministic eviction: least-recently-accessed entry removed when capacity is reached. No randomness.

CLAIMS

Claim 1 (Independent — Method)
A computer-implemented method for deterministic processing of natural-language queries, comprising:
(a) receiving a natural-language query string;
(b) estimating a token count of said query using a word-boundary tokenization function with a fixed token-per-ratio parameter;
(c) determining whether said estimated token count exceeds a predefined token budget;
(d) when said estimated token count exceeds said token budget, applying a sentence-boundary truncation function to produce a reduced query representation within said token budget;
(e) searching a local reference corpus using a deterministic similarity metric for matches to said query;
(f) generating a cryptographic hash of any matched content;
(g) returning said matched content and said cryptographic hash when a match meets a confidence threshold;
(h) when no sufficiently confident local match exists, checking a hash-keyed LRU cache for a previously-stored response;
(i) when a cache hit occurs, returning said cached response;
(j) when no cache hit occurs, routing said query to an external language model, caching the response with said cryptographic hash, and returning said response;
wherein each step is performed deterministically such that an identical input query always yields an identical output.

Claim 2 (Dependent — Hash Verification)
The method of claim 1, wherein said cryptographic hash is computed using SHA-256 and compared against a pre-stored reference hash to verify output integrity before returning to the caller.

Claim 3 (Dependent — Budget Enforcement)
The method of claim 1, wherein said predefined token budget is configurable between 128 and 8,192 tokens, with a default of 512 tokens.

Claim 4 (Dependent — Cache)
The method of claim 1, wherein said LRU cache has a configurable entry limit between 100 and 100,000 entries and a configurable time-to-live between 60 seconds and 86,400 seconds.

Claim 5 (Dependent — Hybrid Routing)
The method of claim 1, wherein said external language model is invoked only when no local match meets said confidence threshold and no cached response exists, minimizing external API calls and reducing token costs by at least 70%.
